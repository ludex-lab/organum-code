# Organum Code v0.1 internal-preview release identity

Status: local product identity and artifact-integrity foundation implemented on
2026-08-22. This is not a public binary release, signing claim, notarization
claim, or multi-platform artifact qualification.

## Frozen preview identity

- product: `organum-code`
- semantic version: `0.1.0-preview.1`
- channel: `internal-preview`
- canonical build runtime: Bun `1.3.14`

The source CLI and compiled standalone expose the same identity:

```bash
organum-code --version
# organum-code 0.1.0-preview.1
```

The same version is projected into ACP client metadata, the bounded Organum
MCP server, default observation producer provenance, and harness provenance.
Backend versions, Hub protocol pins, and provider model versions remain
independent fields and are not rewritten as the product version.

## Local release artifact contract

```bash
bun run build:release-local
```

The command builds the standalone executable and, only from a clean tracked
Git tree, emits beside it:

- `<artifact>.release.json`: `organum-code/release-manifest/v1`
- `<artifact>.sha256`: a conventional SHA-256 checksum line

The manifest binds the full 40-character source commit, `clean: true`, exact
product version/channel, Bun version, platform, architecture, artifact
basename, byte length, and SHA-256. Symlink artifacts, empty files, abbreviated
commits, Bun-version drift, and a file changing during hashing fail closed.
Absolute build paths and timestamps are omitted so identical source/toolchain
inputs do not gain avoidable manifest variance.

CI generates this manifest after the existing standalone smoke on macOS,
Ubuntu, and Windows. CI success establishes that the manifest path is portable;
it does not itself publish or qualify those artifacts for distribution.

The verified local bundle can also be exercised through the explicit-prefix
install, upgrade, one-step rollback, status, and uninstall manager documented in
[`release-installation-lifecycle.md`](./release-installation-lifecycle.md). It
does not use the network, change user configuration, or claim a public
installation channel.

A deterministic platform-named USTAR bundle now carries the standalone,
release metadata, content manifest, and runtime-free POSIX/PowerShell install
and ledger-verified uninstall entrypoints. See
[`offline-release-bundle.md`](./offline-release-bundle.md).

The same archive now carries the complete pinned JavaScriptCore LGPL v2 text,
Bun license, exact Bun/WebKit source coordinates, and relinking instructions.
The public cut can also emit a deterministic source archive containing exactly
its manifest-bound tracked files. See
[`public-binary-relinking.md`](./public-binary-relinking.md).

## Gates still outside this slice

- final distribution review of the source/relink offer
- macOS signing, notarization, and Bun entitlement verification
- Windows signing
- compressed/native platform packages and public installer delivery
- forced-process-interruption recovery during lifecycle state transitions
- release publication, tags, or GitHub Releases

The exact public source archive and unsigned macOS ARM64, Linux X64, and Windows
X64 archives have passed retained staging, archive smoke tests, SHA-256 checks,
and GitHub provenance verification. The signed candidate workflow and its
credential boundary are documented in
[`public-distribution-cut.md`](./public-distribution-cut.md). No external release
is performed by the local manifest or staging commands.

The current public preview channel is instead the cross-platform Bun source
installation documented in [`source-installation.md`](./source-installation.md).
It makes no platform-signing claim and does not publish the staged standalone
archives.
